# HSE checklist management (Phase 5)

The `/#/hse/checklist` route loads visible versions and the selected version through the Phase 3 HSE repository and React Query hooks. The default selection uses the version whose backend state is `published`; `?version=N` preserves a direct selection. The viewer renders backend section and checkpoint IDs, stored order, dates, and counts. Section names follow the current UI language. Checkpoint text is stored only in English by the current schema and is displayed as such.

HSE Engineers can add, edit, and delete content only on a Draft. Supervisors and all users viewing Published or Archived versions have a read-only view. The UI relies on the existing repository preflight and Supabase RLS, constraints, and triggers for authoritative enforcement. Forms reuse the Phase 3 validators. New sections and checkpoints receive the next free order after the current maximum; this does not attempt a multi-request reorder. Concurrent changes can still produce a uniqueness rejection, which the dialog retains and reports.

Read-only inspection of project `dkdzhndvnzgrsvwgdihp` verified on 2026-11-17 that `hse_chain_checklist_items(section_id, template_version)` references sections with **ON DELETE CASCADE**. Section deletion therefore uses one existing repository delete request and warns that its checkpoints will also be removed. The initial live data has Published version 1 and Draft version 2, each with six sections and 29 checkpoints; the UI treats these as data, not limits.

Checklist publishing is unavailable to the browser: version rows are SELECT-only and no publishing RPC exists. Enabling it later requires an authorized transactional backend operation that archives the old Published version, publishes the Draft with a timestamp, and preserves versions used by historical inspections. Transaction-safe manual reordering is also unavailable under the current unique sort-order constraints; a backend transaction or RPC would be required. This phase changes no database objects and performs no live writes.
